# API and Shared Data Contract

## Status

Draft v0.1 for agreement by all three module owners. Once implementation begins, incompatible changes require a new API version or an explicit migration plan.

## General API rules

- Base path: `/v1`.
- JSON field names: `snake_case`.
- Timestamps: ISO 8601 UTC, for example `2026-08-24T09:30:00Z`.
- IDs: opaque UUID v4 strings generated by the application before persistence; clients must not
  infer meaning from them.
- Deterministic URL/content hashes are deduplication keys, never public resource IDs.
- Pagination: cursor-based with `next_cursor`.
- Errors use one envelope and a stable machine-readable code.
- Public responses never contain raw prompts, credentials, internal stack traces, or subscriber addresses.

## Error envelope

```json
{
  "error": {
    "code": "source_item_not_found",
    "message": "The requested update was not found.",
    "request_id": "01K...",
    "details": {}
  }
}
```

## Core endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/v1/health/live` | Process is running; no dependency checks. |
| `GET` | `/v1/health/ready` | Required dependencies are reachable. |
| `GET` | `/v1/updates` | Recent normalized updates with filters and cursor pagination. |
| `GET` | `/v1/updates/{update_id}` | Update details, snapshots, source attribution, and related event. |
| `GET` | `/v1/changes` | Evidence-backed changes, filterable by company/product/date. |
| `GET` | `/v1/changes/{change_id}` | Previous/current facts with citations. |
| `GET` | `/v1/digests` | Published digest summaries. |
| `GET` | `/v1/digests/{digest_id}` | Digest sections and cited claims. |
| `POST` | `/v1/subscriptions` | Start double-opt-in subscription. Always returns a privacy-preserving response. |
| `POST` | `/v1/subscriptions/confirm` | Confirm a signed subscription token. |
| `POST` | `/v1/subscriptions/unsubscribe` | Revoke a signed subscription token. |
| `POST` | `/v1/chat/messages` | Ask a grounded question; response contains citations. |

Collection and digest job controls are not public MVP endpoints. The scheduler invokes authenticated commands in the worker environment.

## Normalized source-item contract

```json
{
  "id": "7c443d0d-8c7e-4cb0-b55d-16df91a40da1",
  "dedupe_key": "sha256:canonical-url-hash",
  "source_id": "openai_news",
  "publisher": "OpenAI",
  "title": "Example announcement",
  "canonical_url": "https://example.com/news/example",
  "published_at": "2026-08-24T08:00:00Z",
  "updated_at": null,
  "first_fetched_at": "2026-08-24T08:05:00Z",
  "latest_snapshot_id": "96377473-b3ac-4133-9f7d-63f28edbdc39",
  "event_id": null,
  "authors": [],
  "tags": ["model_release"],
  "language": "en"
}
```

Required invariants:

- `canonical_url` is normalized before identity comparison.
- `dedupe_key` is derived from the normalized canonical URL and has a database uniqueness
  constraint. It may be recalculated if canonicalization rules change; `id` never changes.
- Publisher-provided publication time remains distinct from fetch time.
- An item may have multiple snapshots.
- A different publisher covering the same event is not deleted as a duplicate.
- `event_id` is nullable until the intelligence workflow groups independently published items.

## Snapshot contract

```json
{
  "id": "96377473-b3ac-4133-9f7d-63f28edbdc39",
  "source_item_id": "7c443d0d-8c7e-4cb0-b55d-16df91a40da1",
  "fetched_at": "2026-08-24T08:05:00Z",
  "content_hash": "sha256:...",
  "content_text": "Clean source text",
  "raw_location": "raw/openai_news/2026/08/24/...",
  "etag": null,
  "last_modified": null,
  "collector_version": "0.1.0"
}
```

Snapshots are immutable. The API may omit `content_text` from list responses.

## Change contract

`ChangeSet` is the internal aggregate produced by the intelligence module. A `Change` is one
field-level API projection within that aggregate. `GET /v1/changes` returns change summaries;
`GET /v1/changes/{change_id}` returns the containing change set with its evidence. Both names must
map explicitly in the shared model and contract tests rather than being used interchangeably.

```json
{
  "id": "2d61331d-cbe7-4714-a82d-118b5f974523",
  "change_set_id": "f1d00664-5d15-4d36-a61f-2c340a031163",
  "subject": {
    "company": "Example AI",
    "product": "Example Model"
  },
  "field": "context_window_tokens",
  "change_type": "increased",
  "previous": {
    "value": 128000,
    "observed_at": "2026-07-01T00:00:00Z",
    "snapshot_id": "0b931da4-ca9c-4541-8249-53a7ea70d606",
    "source_url": "https://example.com/old"
  },
  "current": {
    "value": 256000,
    "observed_at": "2026-08-24T00:00:00Z",
    "snapshot_id": "96377473-b3ac-4133-9f7d-63f28edbdc39",
    "source_url": "https://example.com/new"
  },
  "confidence": 0.98,
  "review_status": "validated"
}
```

The previous value may be `null` only when the response explicitly says the fact was not previously disclosed. Absence of evidence must not be described as a zero or a negative fact.

Example detail wrapper returned by `GET /v1/changes/{change_id}`:

```json
{
  "id": "f1d00664-5d15-4d36-a61f-2c340a031163",
  "subject": {"company": "Example AI", "product": "Example Model"},
  "changes": [{"id": "2d61331d-cbe7-4714-a82d-118b5f974523"}],
  "previous_snapshot_ids": ["0b931da4-ca9c-4541-8249-53a7ea70d606"],
  "current_snapshot_ids": ["96377473-b3ac-4133-9f7d-63f28edbdc39"],
  "review_status": "validated"
}
```

The abbreviated object in `changes` above only avoids repeating the full Change example. The real
response contains complete Change objects and is protected by a contract test.

## Extracted fact contract

Facts created by deterministic code use `extraction_method: "deterministic"`. Facts created with
an LLM must also record the provider-neutral model identifier and versioned prompt so evaluations
can be reproduced.

```json
{
  "id": "7a5bbb61-d20d-4bd3-93cf-e31236b98f0d",
  "snapshot_id": "96377473-b3ac-4133-9f7d-63f28edbdc39",
  "field": "context_window_tokens",
  "value": 256000,
  "extraction_method": "llm_structured_output",
  "extraction_model": "provider/model-version",
  "prompt_version": "fact-extraction-v1"
}
```

## Digest contract

Digest list and detail responses use a wrapper rather than returning unowned claim arrays:

```json
{
  "id": "62b46ee2-b48d-47cf-bc55-44106b43ea3e",
  "digest_date": "2026-08-24",
  "status": "published",
  "title": "AI Daily Digest — 24 August 2026",
  "claims": [
    {
      "id": "261cb600-c1de-4c79-97c7-f6af8b35724a",
      "text": "Example Model now supports a 256k-token context window.",
      "citation_snapshot_ids": ["96377473-b3ac-4133-9f7d-63f28edbdc39"],
      "validation_status": "supported"
    }
  ]
}
```

## Digest claim contract

```json
{
  "id": "261cb600-c1de-4c79-97c7-f6af8b35724a",
  "text": "Example Model now supports a 256k-token context window.",
  "citation_snapshot_ids": ["96377473-b3ac-4133-9f7d-63f28edbdc39"],
  "validation_status": "supported"
}
```

Every factual claim requires at least one valid citation. A digest containing an `unsupported` claim cannot enter `published` status automatically.

## Subscription request contracts

Start double opt-in:

```json
{
  "email": "reader@example.com",
  "consent_to_daily_digest": true
}
```

The server records `consented_at` using its own UTC clock; it does not trust a client-supplied
consent timestamp. Whether or not the address already exists, the response is the same:

```json
{
  "message": "If the address is eligible, a confirmation email will be sent."
}
```

Confirm and unsubscribe each accept a signed, single-purpose token:

```json
{
  "token": "opaque-signed-token"
}
```

Raw tokens are never stored. Their hashes, purpose, expiry, and use/revocation time are stored.

## Chat request contract

```json
{
  "message": "What changed in Example Model's context window?",
  "session_id": null
}
```

`message` is required and size-limited. `session_id` is an optional opaque UUID v4 belonging to
the same anonymous or authenticated client context; it must not grant access to another session.

## Chat response contract

```json
{
  "answer": "The context window increased from 128k to 256k tokens.",
  "citations": [
    {
      "source_url": "https://example.com/new",
      "snapshot_id": "01K...",
      "title": "Example announcement"
    }
  ],
  "request_id": "d0d68b1f-42cc-4b20-a32a-ceadfac542aa"
}
```

If the stored evidence is insufficient, the correct response states that the answer is not established. The chat must not silently use uncited model knowledge.

## Contract-change process

1. Open a focused issue describing the consumer impact.
2. Update this document and affected Pydantic/OpenAPI schemas in the same PR.
3. Add or update contract tests.
4. Obtain review from at least one other module owner.
5. Use additive changes where possible. For a breaking response change, introduce `/v2` or a documented migration window.
